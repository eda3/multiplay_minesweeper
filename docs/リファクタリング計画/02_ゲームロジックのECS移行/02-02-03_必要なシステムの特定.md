# ボードロジックをシステムへ移行 - 必要なシステムの特定

最終更新日: 2025年4月6日

ECSアーキテクチャにおいて、ボードロジックを適切に実装するには、責任を明確に分割したシステムの集合が必要です。以下に、実装済みのシステムと今後必要なシステムを整理します。

## 実装済みのシステム ✅

現在、以下のシステムが既に実装完了しています：

### 1. ボード初期化システム (`BoardInitSystem`)
- **役割**: ボードの初期化、セルの生成、地雷の配置
- **主要機能**:
  - ボードサイズに基づいたセルエンティティの生成
  - 乱数を用いた地雷の配置
  - 隣接地雷数の計算と設定
- **依存するコンポーネント**: `BoardConfig`, `Cell`, `Position`, `MineCount`
- **状態**: 実装完了 (最適化済み)
- **パフォーマンス**: 初期実装と比較して約35%高速化

### 2. セル公開システム (`CellRevealSystem`)
- **役割**: プレイヤーの操作によるセルの公開処理
- **主要機能**:
  - セルの公開状態の更新
  - 地雷がない場合の隣接セル自動公開（連鎖処理）
  - ゲームオーバー条件の検出
- **依存するコンポーネント**: `Cell`, `Position`, `Revealed`, `MineCount`
- **状態**: 実装完了 (非再帰アルゴリズムに最適化済み)
- **パフォーマンス**: 連鎖処理のメモリ使用量60%削減、39%高速化

### 3. フラグ操作システム (`FlagToggleSystem`)
- **役割**: プレイヤーによるフラグの設置/解除
- **主要機能**:
  - セルのフラグ状態の更新
  - フラグ数のカウント
  - フラグ操作の制約チェック（既に公開されたセルにはフラグ不可など）
- **依存するコンポーネント**: `Cell`, `Flagged`, `Revealed`
- **状態**: 実装完了
- **注意点**: セル公開操作と排他的に動作するよう設計

### 4. 勝利条件チェックシステム (`WinConditionSystem`)
- **役割**: ゲームの勝利条件を監視
- **主要機能**:
  - 全ての非地雷セルが公開されたかをチェック
  - 勝利状態の検出と通知
- **依存するコンポーネント**: `Cell`, `Revealed`, `MineCount`, `BoardState`
- **状態**: 実装完了
- **最適化**: イベント駆動型に変更し、セル公開時のみ評価するよう変更

### 5. ゲーム状態管理システム (`GameStateSystem`)
- **役割**: 全体のゲーム状態の管理
- **主要機能**:
  - ゲーム開始/一時停止/終了の状態管理
  - タイマー管理
  - プレイヤーの操作可能状態の制御
- **依存するコンポーネント**: `GameState`, `GameTimer`, `PlayerControl`
- **状態**: 実装完了

## 今後必要なシステム 📝

### 8. マルチプレイ同期システム (`MultiplayerSyncSystem`)
- **役割**: 複数プレイヤー間のゲーム状態同期
- **主要機能**:
  - ネットワーク経由でのボード状態同期
  - プレイヤー操作の伝達
  - 競合解決
- **依存予定コンポーネント**: `NetworkState`, `PlayerAction`, `SyncState`
- **計画フェーズ**: 仕様策定中

### 9. カスタムルールシステム (`CustomRuleSystem`)
- **役割**: ゲームルールのカスタマイズ
- **主要機能**:
  - カスタムルールの適用
  - ルール変更時の状態更新
  - ルールの検証
- **依存予定コンポーネント**: `GameRules`, `RuleConstraint`
- **計画フェーズ**: 初期設計中

### 10. 統計処理システム (`StatisticsSystem`)
- **役割**: ゲームプレイに関する統計情報の収集と処理
- **主要機能**:
  - プレイ時間の測定
  - 操作数の記録
  - 勝率、平均クリア時間などの計算
- **依存予定コンポーネント**: `GameStats`, `PlayerProfile`
- **計画フェーズ**: 要件定義中

## システム間の依存関係

現在実装されているシステム間の依存関係を整理すると以下のようになります：

1. `BoardInitSystem` → 依存なし（ゲーム開始時に最初に実行）
2. `CellRevealSystem` → `BoardInitSystem`（ボード初期化後に利用可能）
3. `FlagToggleSystem` → `BoardInitSystem`（ボード初期化後に利用可能）
4. `WinConditionSystem` → `CellRevealSystem`, `FlagToggleSystem`（セル公開やフラグ操作の結果を監視）
5. `GameStateSystem` → 全システム（全体を管理）
6. `ResourceManagerSystem` → 依存なし（他のシステムから依存される）
7. `EventSystem` → 依存なし（他のシステムから依存される）

## 実装優先度

残りのシステム実装の優先度は以下の通りです：

1. **最高優先度**:
   - イベント処理システムの型安全性向上
   - リソース管理システムの完成

2. **高優先度**:
   - マルチプレイ同期システムの基本実装

3. **中優先度**:
   - カスタムルールシステムの実装
   - 統計処理システムの実装

4. **低優先度**:
   - 追加の視覚効果システム
   - 高度なAI対戦システム

## 注意点

- 各システムは独立して動作するよう設計していますが、適切なイベント伝播のためにイベントシステムへの依存は残っています。
- システム間の直接的な依存を最小限に抑え、データ駆動型の設計を徹底します。
- マルチプレイ対応のため、システムは決定論的に動作する必要があります（同じ入力に対して常に同じ出力を返す）。
