# ボードロジックをシステムへ移行 - ボードリソースの設計

最終更新日: 2025年4月5日

## 概要

ECSアーキテクチャにおいて、リソースはシステム間で共有される状態やグローバルなデータを表現します。ボードロジックにおいては、複数のシステムが共通して参照・変更する情報がリソースとして設計されます。

このドキュメントでは、マインスイーパーのボードロジック移行に必要なリソースの詳細設計と実装方針について説明します。

## リソースの役割

ECSアーキテクチャにおけるリソースは以下の役割を持ちます：

- 複数のシステムで共有されるグローバル状態の管理
- ゲーム全体に影響する設定や構成情報の保持
- システム間の直接的な依存関係を減らすためのデータストア
- イベントやメッセージの伝達媒体

## ボードリソース一覧

マインスイーパーのボードロジックには、以下のリソースが必要です：

| リソース名 | 役割 | アクセスするシステム |
|------------|------|----------------------|
| `BoardConfig` | ボードの設定情報 | BoardInitSystem, BoardDisplaySystem |
| `GameState` | ゲームの状態管理 | 全システム |
| `RandomGenerator` | 地雷配置のための乱数生成 | BoardRandomizeSystem |
| `InputEvents` | ユーザー入力イベントのキュー | InputSystem, CellRevealSystem, FlagToggleSystem |
| `BoardStatistics` | ゲームの統計情報 | GameStateSystem, UIUpdateSystem |
| `Timer` | ゲーム経過時間の管理 | TimerSystem, UIUpdateSystem |

## リソース詳細設計

### 1. BoardConfig

ボードの基本設定を保持するリソースです。ゲーム開始時に設定され、通常はゲーム中に変更されません。

```rust
/// ボードの基本設定を保持するリソース
#[derive(Clone, Debug)]
pub struct BoardConfig {
    /// ボードの幅（セル数）
    pub width: usize,
    /// ボードの高さ（セル数）
    pub height: usize,
    /// ボード上の地雷数
    pub mine_count: usize,
    /// 難易度レベル（Easy、Medium、Hard、Custom）
    pub difficulty: DifficultyLevel,
    /// 最初のクリックで地雷に当たらないようにするフラグ
    pub safe_first_click: bool,
}

/// 難易度レベル
#[derive(Clone, Debug, PartialEq, Eq)]
pub enum DifficultyLevel {
    Easy,
    Medium,
    Hard,
    Custom,
}

impl BoardConfig {
    /// 新しいボード設定を作成
    pub fn new(width: usize, height: usize, mine_count: usize) -> Self {
        let difficulty = if width == 9 && height == 9 && mine_count == 10 {
            DifficultyLevel::Easy
        } else if width == 16 && height == 16 && mine_count == 40 {
            DifficultyLevel::Medium
        } else if width == 30 && height == 16 && mine_count == 99 {
            DifficultyLevel::Hard
        } else {
            DifficultyLevel::Custom
        };

        Self {
            width,
            height,
            mine_count,
            difficulty,
            safe_first_click: true,
        }
    }
    
    /// プリセット難易度からボード設定を作成
    pub fn from_difficulty(difficulty: DifficultyLevel) -> Self {
        match difficulty {
            DifficultyLevel::Easy => Self::new(9, 9, 10),
            DifficultyLevel::Medium => Self::new(16, 16, 40),
            DifficultyLevel::Hard => Self::new(30, 16, 99),
            DifficultyLevel::Custom => panic!("Custom difficulty requires explicit dimensions"),
        }
    }
    
    /// ボード上の総セル数を取得
    pub fn total_cells(&self) -> usize {
        self.width * self.height
    }
    
    /// 有効な座標かチェック
    pub fn is_valid_position(&self, x: usize, y: usize) -> bool {
        x < self.width && y < self.height
    }
}
```

#### 設計上の考慮点：

- **不変性**: ゲーム開始後は変更されないため、システムは安全に参照可能
- **拡張性**: 将来的な機能追加（カスタムルールなど）に対応できるよう設計
- **ユーティリティメソッド**: 頻繁に使用される計算や検証を集約

### 2. GameState

ゲームの現在の状態を管理するリソースです。ゲームの進行状況やプレイヤーの操作により変化します。

```rust
/// ゲームの状態を表すリソース
#[derive(Clone, Debug, PartialEq, Eq)]
pub struct GameState {
    /// ゲームの現在の状態
    pub status: GameStatus,
    /// 残りのフラグ数
    pub remaining_flags: usize,
    /// 第一クリックが行われたかどうか
    pub first_click_made: bool,
    /// 公開されたセル数
    pub revealed_cells: usize,
}

/// ゲームステータス
#[derive(Clone, Debug, PartialEq, Eq)]
pub enum GameStatus {
    /// 初期化中
    Initializing,
    /// プレイ中
    Playing,
    /// 勝利
    Won,
    /// 敗北
    Lost,
    /// 一時停止
    Paused,
}

impl GameState {
    /// 新しいゲーム状態を作成
    pub fn new(mine_count: usize) -> Self {
        Self {
            status: GameStatus::Initializing,
            remaining_flags: mine_count,
            first_click_made: false,
            revealed_cells: 0,
        }
    }
    
    /// ゲームが進行中かどうか
    pub fn is_active(&self) -> bool {
        matches!(self.status, GameStatus::Playing)
    }
    
    /// ゲームが終了したかどうか
    pub fn is_game_over(&self) -> bool {
        matches!(self.status, GameStatus::Won | GameStatus::Lost)
    }
    
    /// フラグを立てる（残りフラグ数を減らす）
    pub fn place_flag(&mut self) -> bool {
        if self.remaining_flags > 0 {
            self.remaining_flags -= 1;
            true
        } else {
            false
        }
    }
    
    /// フラグを外す（残りフラグ数を増やす）
    pub fn remove_flag(&mut self) {
        self.remaining_flags += 1;
    }
    
    /// セルが公開されたことを記録
    pub fn cell_revealed(&mut self) {
        self.revealed_cells += 1;
    }
}
```

#### 設計上の考慮点：

- **状態遷移**: 明確な状態遷移を定義し、不正な状態変化を防止
- **不変条件**: 残りフラグ数や公開セル数などの不変条件を維持
- **状態クエリ**: システムが頻繁に必要とする状態クエリメソッドを提供

### 3. RandomGenerator

地雷配置など、ゲーム内の乱数生成を担当するリソースです。シード値を設定することで、テスト時などに決定論的な動作が可能です。

```rust
/// 乱数生成を管理するリソース
pub struct RandomGenerator {
    rng: StdRng,
}

impl RandomGenerator {
    /// デフォルトのランダムシードで初期化
    pub fn new() -> Self {
        Self {
            rng: StdRng::from_entropy(),
        }
    }
    
    /// 特定のシード値で初期化（テスト用）
    pub fn with_seed(seed: u64) -> Self {
        Self {
            rng: StdRng::seed_from_u64(seed),
        }
    }
    
    /// 0からmax-1までの範囲の乱数を生成
    pub fn gen_range(&mut self, max: usize) -> usize {
        self.rng.gen_range(0..max)
    }
    
    /// 2次元配列の範囲で乱数位置を生成
    pub fn gen_position(&mut self, width: usize, height: usize) -> Position {
        let x = self.rng.gen_range(0..width);
        let y = self.rng.gen_range(0..height);
        Position::new(x, y)
    }
    
    /// 指定された位置を除く乱数位置を生成（最初のクリックが安全になるよう）
    pub fn gen_position_except(&mut self, width: usize, height: usize, 
                              excluded: &[Position]) -> Position {
        loop {
            let pos = self.gen_position(width, height);
            if !excluded.contains(&pos) {
                return pos;
            }
        }
    }
    
    /// 配列をシャッフル
    pub fn shuffle<T>(&mut self, slice: &mut [T]) {
        slice.shuffle(&mut self.rng);
    }
}
```

#### 設計上の考慮点：

- **決定論的テスト**: シード値を固定することでテスト時に再現可能な動作
- **特殊条件**: 「最初のクリックは安全」などのルールをサポートする機能
- **汎用性**: 様々な乱数生成ニーズに対応できるメソッド群

### 4. InputEvents

ユーザー入力イベントを処理するためのキューを提供するリソースです。システム間でのイベント伝播を可能にします。

```rust
/// 入力イベントタイプ
#[derive(Clone, Debug)]
pub enum InputEventType {
    /// セルを左クリック（公開）
    Reveal(Position),
    /// セルを右クリック（フラグ）
    Flag(Position),
    /// ゲームリセット
    Reset,
    /// 一時停止/再開
    TogglePause,
}

/// 入力イベントキュー
#[derive(Default)]
pub struct InputEvents {
    events: VecDeque<InputEventType>,
}

impl InputEvents {
    /// 新しい入力イベントキューを作成
    pub fn new() -> Self {
        Self {
            events: VecDeque::new(),
        }
    }
    
    /// イベントをキューに追加
    pub fn push(&mut self, event: InputEventType) {
        self.events.push_back(event);
    }
    
    /// キューからイベントを取得
    pub fn pop(&mut self) -> Option<InputEventType> {
        self.events.pop_front()
    }
    
    /// 複数のイベントを一度に処理
    pub fn drain(&mut self) -> impl Iterator<Item = InputEventType> + '_ {
        self.events.drain(..)
    }
    
    /// キューが空かどうか
    pub fn is_empty(&self) -> bool {
        self.events.is_empty()
    }
    
    /// キューをクリア
    pub fn clear(&mut self) {
        self.events.clear();
    }
}
```

#### 設計上の考慮点：

- **デカップリング**: 入力処理とロジック処理を分離し、システム間の依存を減少
- **バッファリング**: 複数フレームにまたがる入力処理をサポート
- **型安全性**: イベントタイプを明示的に定義し、型エラーを防止

### 5. BoardStatistics

ゲームの統計情報を追跡するリソースです。ユーザーインターフェースの更新やゲーム分析に利用されます。

```rust
/// ボード統計情報を管理するリソース
#[derive(Default, Clone, Debug)]
pub struct BoardStatistics {
    /// ゲーム開始時刻
    pub start_time: Option<Instant>,
    /// ゲーム終了時刻
    pub end_time: Option<Instant>,
    /// 総プレイ時間（一時停止を除く）
    pub play_time: Duration,
    /// クリック回数
    pub click_count: usize,
    /// フラグ設置回数
    pub flag_count: usize,
    /// フラグ除去回数
    pub unflag_count: usize,
    /// 連鎖公開で公開されたセル数
    pub cascade_revealed: usize,
}

impl BoardStatistics {
    /// 新しい統計情報を作成
    pub fn new() -> Self {
        Self::default()
    }
    
    /// ゲーム開始を記録
    pub fn start_game(&mut self) {
        self.start_time = Some(Instant::now());
        self.end_time = None;
        self.play_time = Duration::ZERO;
        self.click_count = 0;
        self.flag_count = 0;
        self.unflag_count = 0;
        self.cascade_revealed = 0;
    }
    
    /// ゲーム終了を記録
    pub fn end_game(&mut self) {
        if let Some(start) = self.start_time {
            self.end_time = Some(Instant::now());
            self.play_time = self.end_time.unwrap().duration_since(start);
        }
    }
    
    /// クリックを記録
    pub fn record_click(&mut self) {
        self.click_count += 1;
    }
    
    /// フラグ設置を記録
    pub fn record_flag(&mut self) {
        self.flag_count += 1;
    }
    
    /// フラグ除去を記録
    pub fn record_unflag(&mut self) {
        self.unflag_count += 1;
    }
    
    /// 連鎖公開を記録
    pub fn record_cascade(&mut self, count: usize) {
        self.cascade_revealed += count;
    }
    
    /// 現在のプレイ時間を取得
    pub fn current_play_time(&self) -> Duration {
        if let Some(start) = self.start_time {
            if let Some(end) = self.end_time {
                end.duration_since(start)
            } else {
                Instant::now().duration_since(start)
            }
        } else {
            Duration::ZERO
        }
    }
}
```

#### 設計上の考慮点：

- **パフォーマンス分析**: プレイデータを収集し、ゲーム体験の分析に活用
- **UI連携**: ユーザーに表示する統計情報の管理
- **デバッグ支援**: 開発中のデバッグや性能測定に役立つ情報の提供

### 6. Timer

ゲーム時間を管理するリソースです。一時停止機能などをサポートします。

```rust
/// ゲーム時間を管理するリソース
#[derive(Debug, Clone)]
pub struct Timer {
    /// 開始時刻
    start_time: Option<Instant>,
    /// 一時停止時の経過時間
    paused_duration: Duration,
    /// 一時停止状態かどうか
    is_paused: bool,
    /// 一時停止開始時刻
    pause_start: Option<Instant>,
}

impl Timer {
    /// 新しいタイマーを作成
    pub fn new() -> Self {
        Self {
            start_time: None,
            paused_duration: Duration::ZERO,
            is_paused: false,
            pause_start: None,
        }
    }
    
    /// タイマーを開始
    pub fn start(&mut self) {
        self.start_time = Some(Instant::now());
        self.paused_duration = Duration::ZERO;
        self.is_paused = false;
        self.pause_start = None;
    }
    
    /// タイマーをリセット
    pub fn reset(&mut self) {
        *self = Self::new();
    }
    
    /// タイマーを一時停止
    pub fn pause(&mut self) {
        if !self.is_paused && self.start_time.is_some() {
            self.is_paused = true;
            self.pause_start = Some(Instant::now());
        }
    }
    
    /// タイマーを再開
    pub fn resume(&mut self) {
        if self.is_paused {
            if let Some(pause_time) = self.pause_start {
                self.paused_duration += Instant::now().duration_since(pause_time);
                self.is_paused = false;
                self.pause_start = None;
            }
        }
    }
    
    /// 現在の経過時間を取得
    pub fn elapsed(&self) -> Duration {
        if let Some(start) = self.start_time {
            if self.is_paused {
                if let Some(pause_time) = self.pause_start {
                    let active_time = pause_time.duration_since(start);
                    active_time - self.paused_duration
                } else {
                    Duration::ZERO
                }
            } else {
                let now = Instant::now();
                now.duration_since(start) - self.paused_duration
            }
        } else {
            Duration::ZERO
        }
    }
    
    /// タイマーが動作中かどうか
    pub fn is_running(&self) -> bool {
        self.start_time.is_some() && !self.is_paused
    }
    
    /// タイマーが一時停止中かどうか
    pub fn is_paused(&self) -> bool {
        self.is_paused
    }
}
```

#### 設計上の考慮点：

- **一時停止機能**: ゲームの一時停止・再開をサポート
- **正確な時間計測**: 一時停止時間を除外した正確なプレイ時間の計測
- **状態管理**: タイマーの状態（実行中、停止中など）の明確な管理

## リソース間の関係

リソース間には以下のような関係があります：

1. `BoardConfig`は初期化時に`GameState`の初期値（残りフラグ数など）を決定します
2. `RandomGenerator`は`BoardConfig`に基づいて地雷の位置を決定します
3. `InputEvents`は`GameState`の状態に基づいて処理されます（ゲームオーバー時は無視するなど）
4. `BoardStatistics`は`GameState`や`Timer`のデータを参照して統計情報を更新します

## リソースへのアクセスパターン

各システムがリソースにどのようにアクセスするかを以下に示します：

| システム | リソース | アクセスモード | 目的 |
|---------|----------|--------------|------|
| BoardInitSystem | BoardConfig | 読み取り | ボードサイズの取得 |
| BoardRandomizeSystem | BoardConfig<br>RandomGenerator<br>GameState | 読み取り<br>読み書き<br>読み取り | 地雷配置のパラメータ取得<br>乱数生成<br>初回クリック情報の確認 |
| InputSystem | InputEvents<br>GameState | 書き込み<br>読み取り | イベント追加<br>ゲーム状態の確認 |
| CellRevealSystem | InputEvents<br>GameState | 読み取り<br>読み書き | Revealイベント処理<br>ゲーム状態の更新 |
| FlagToggleSystem | InputEvents<br>GameState | 読み取り<br>読み書き | Flagイベント処理<br>残りフラグ数の更新 |
| CascadeSystem | GameState<br>BoardStatistics | 読み取り<br>書き込み | ゲーム状態の確認<br>連鎖公開の統計記録 |
| WinConditionSystem | GameState<br>BoardStatistics<br>Timer | 読み書き<br>書き込み<br>読み取り | 勝利条件チェック・状態更新<br>統計情報の記録<br>ゲーム時間の取得 |
| TimerSystem | Timer<br>GameState | 読み書き<br>読み取り | 時間更新<br>ゲーム状態の確認 |
| UIUpdateSystem | GameState<br>BoardStatistics<br>Timer | 読み取り<br>読み取り<br>読み取り | UI表示内容の決定 |

## リソース実装の考慮点

### 1. スレッドセーフティ

ECSフレームワークによっては、並列実行をサポートしているものがあります。その場合、リソースへの同時アクセスを考慮する必要があります：

```rust
// リソースをスレッドセーフにするための実装例
#[derive(Default)]
pub struct ThreadSafeGameState {
    inner: Mutex<GameState>,
}

impl ThreadSafeGameState {
    pub fn new(mine_count: usize) -> Self {
        Self {
            inner: Mutex::new(GameState::new(mine_count)),
        }
    }
    
    pub fn with_lock<F, R>(&self, f: F) -> R
    where
        F: FnOnce(&mut GameState) -> R,
    {
        let mut guard = self.inner.lock().unwrap();
        f(&mut guard)
    }
}
```

### 2. 変更検知

UIの効率的な更新など、リソースの変更を検知する必要がある場合があります：

```rust
// 変更を検知するラッパーの例
#[derive(Clone, Debug)]
pub struct Dirty<T> {
    value: T,
    is_dirty: bool,
}

impl<T> Dirty<T> {
    pub fn new(value: T) -> Self {
        Self {
            value,
            is_dirty: true, // 初期状態は常にdirty
        }
    }
    
    pub fn get(&self) -> &T {
        &self.value
    }
    
    pub fn get_mut(&mut self) -> &mut T {
        self.is_dirty = true;
        &mut self.value
    }
    
    pub fn is_dirty(&self) -> bool {
        self.is_dirty
    }
    
    pub fn mark_clean(&mut self) {
        self.is_dirty = false;
    }
}
```

### 3. リソースのフェッチパターン

システムがリソースを取得する際のパターンを統一することで、コードの一貫性を保ちます：

```rust
// リソースフェッチパターンの例
fn run_system(world: &mut World) {
    // 必須リソース
    let board_config = world.get_resource::<BoardConfig>()
        .expect("BoardConfig resource not found");
    
    // オプショナルリソース（存在しない場合はデフォルト値を使用）
    let stats = world.get_resource_or_insert_with(BoardStatistics::default);
    
    // 書き込みアクセスが必要なリソース
    let mut game_state = world.get_resource_mut::<GameState>()
        .expect("GameState resource not found");
    
    // リソースを使った処理
    // ...
}
```

## まとめ

このドキュメントでは、マインスイーパーのボードロジックをECSアーキテクチャに移行する際に必要なリソースの設計について詳細に説明しました。各リソースは明確な責任を持ち、システム間での状態共有を効率的に行います。

適切に設計されたリソースは、システム間の結合度を下げ、コードの保守性と拡張性を向上させます。また、明確に定義されたリソースの使用パターンは、デバッグを容易にし、バグの発生を減らす効果があります。

次のステップでは、これらのリソースを利用する具体的なシステムの実装に進みます。
