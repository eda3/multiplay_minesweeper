# ボードロジックをシステムへ移行 - ボード関連コンポーネントの設計

最終更新日: 2025年4月5日

## コンポーネント設計の原則

ECSパターンにおいて、コンポーネントは純粋なデータ構造であり、振る舞いを持ちません。以下の原則に従ってコンポーネントを設計します：

- データのみを含む（メソッドは最小限に）
- シンプルで単一責任
- シリアライズ/デシリアライズ可能
- イミュータブルな設計（可能な限り）

## ボード関連コンポーネント

マインスイーパーのボードロジックには、以下の3つの主要コンポーネントが必要です。

### 1. CellStateComponent

セルの現在の状態（公開状態、フラグ状態など）を表します。

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CellStateComponent {
    /// セルが公開されているかどうか
    pub is_revealed: bool,
    
    /// セルにフラグが立てられているかどうか
    pub is_flagged: bool,
    
    /// セルに疑問符が付けられているかどうか
    pub is_questioned: bool,
}

impl CellStateComponent {
    /// 新しいセル状態を作成（デフォルトは非公開、フラグなし）
    pub fn new() -> Self {
        Self {
            is_revealed: false,
            is_flagged: false,
            is_questioned: false,
        }
    }
}

impl Component for CellStateComponent {
    fn as_any(&self) -> &dyn Any { self }
    fn as_any_mut(&mut self) -> &mut dyn Any { self }
    fn clone_box(&self) -> Box<dyn Component> {
        Box::new(self.clone())
    }
}
```

### 2. CellContentComponent

セルの内容（地雷または周囲の地雷数）を表します。

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub enum CellContent {
    /// 地雷
    Mine,
    
    /// 周囲の地雷数（0は空白セル）
    Empty(u8),
}

#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct CellContentComponent {
    /// セルの内容
    pub content: CellContent,
}

impl CellContentComponent {
    /// 地雷セルを作成
    pub fn mine() -> Self {
        Self { content: CellContent::Mine }
    }
    
    /// 空のセルを作成（周囲の地雷数を指定）
    pub fn empty(adjacent_mines: u8) -> Self {
        Self { content: CellContent::Empty(adjacent_mines) }
    }
    
    /// 地雷かどうかを確認
    pub fn is_mine(&self) -> bool {
        matches!(self.content, CellContent::Mine)
    }
    
    /// 周囲の地雷数を取得（地雷の場合は0）
    pub fn adjacent_mines(&self) -> u8 {
        match self.content {
            CellContent::Empty(count) => count,
            CellContent::Mine => 0,
        }
    }
}

impl Component for CellContentComponent {
    fn as_any(&self) -> &dyn Any { self }
    fn as_any_mut(&mut self) -> &mut dyn Any { self }
    fn clone_box(&self) -> Box<dyn Component> {
        Box::new(self.clone())
    }
}
```

### 3. GridPositionComponent

セルのグリッド上の位置を表します。

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct GridPositionComponent {
    /// グリッド上の行（上から下へ）
    pub row: usize,
    
    /// グリッド上の列（左から右へ）
    pub col: usize,
}

impl GridPositionComponent {
    /// 新しいグリッド位置を作成
    pub fn new(row: usize, col: usize) -> Self {
        Self { row, col }
    }
    
    /// 指定された位置からのマンハッタン距離を計算
    pub fn distance_from(&self, other: &GridPositionComponent) -> usize {
        let row_diff = if self.row > other.row { self.row - other.row } else { other.row - self.row };
        let col_diff = if self.col > other.col { self.col - other.col } else { other.col - self.col };
        row_diff + col_diff
    }
}

impl Component for GridPositionComponent {
    fn as_any(&self) -> &dyn Any { self }
    fn as_any_mut(&mut self) -> &mut dyn Any { self }
    fn clone_box(&self) -> Box<dyn Component> {
        Box::new(self.clone())
    }
}
```

## コンポーネント関係図

これらのコンポーネントは、以下のようにセルエンティティを構成します：

```
+----------------------+
|      CellEntity      |
+----------------------+
| GridPositionComponent|
| CellStateComponent   |
| CellContentComponent |
+----------------------+
```

各セルエンティティは、これら3つのコンポーネントを持ちます。これにより、セルの位置、状態、内容を分離して管理することができます。

## システムとコンポーネントの関係

- **BoardInitSystem**: 全てのコンポーネントを作成・初期化
- **CellRevealSystem**: CellStateComponentを更新、CellContentComponentを読み取り
- **FlagToggleSystem**: CellStateComponentを更新
- **WinConditionSystem**: CellStateComponentとCellContentComponentを読み取り
